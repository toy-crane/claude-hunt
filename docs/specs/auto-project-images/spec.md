# 프로젝트 이미지 자동 캡처

## 목적

LG전자 클래스 수강생처럼 회사 보안 때문에 스크린샷을 직접 올리지 못하는 소유자도 프로젝트를 이미지와 함께 공개할 수 있게 한다. 소유자가 이미지를 비워 두고 제출하면 시스템이 프로젝트 URL을 직접 열어 첫 화면을 대표 이미지로 만들고, 공개 뒤에는 실제로 조작해야 보이는 하이라이트 화면을 찾아 갤러리를 채운다.

## 연결된 기준

- [prototype.html](prototype.html) — 제출·상세·편집 화면의 구성, 상태, 문구를 정한다. 화면 배치와 상태 전환은 이 프로토타입을 따른다.
- [project-publishing](../../decisions/project-publishing.md) — 이미지 1~5장 불변식, 이미지를 비워 두었을 때 첫 화면을 기다렸다가 공개하는 규칙, 소유자 변경 우선 규칙을 정한다.
- [project-url-capture](../../decisions/project-url-capture.md) — 외부 URL을 격리된 Vercel Sandbox에서만 여는 규칙, 첫 화면은 결정론적으로·하이라이트는 Haiku 5.5 에이전트로 찍는 구분, 에이전트 행동 경계를 정한다.
- [GLOSSARY.md](../../../GLOSSARY.md) — `대표 이미지`, `프로젝트`, `클래스`의 뜻.
- [PRODUCT.md](../../../PRODUCT.md) — 이 작업에 적용되는 원칙은 "프로젝트 제출의 마찰을 낮춘다"와 "프로젝트가 장식이나 운영 도구보다 먼저 보이게 한다"이다.

## 기대 결과

- 이미지를 한 장도 올리지 않은 소유자도 프로젝트를 제출할 수 있고, 공개된 프로젝트에는 항상 대표 이미지가 있다.
- 공개 직후 몇 분 안에 갤러리가 프로젝트의 실제 사용 장면(게임 진행·결과, 검색·계산 결과 등)으로 채워진다.
- 직접 이미지를 올리는 소유자의 흐름은 지금과 같다.

## 승인된 범위

### 제출

- `스크린샷` 항목은 필수가 아니라 선택이다. 라벨 옆에 `(선택)`을 표시한다.
- 이미지를 1장 이상 올리고 제출하면 지금과 똑같이 공개되며 자동 캡처는 일어나지 않는다.
- 이미지 없이 제출하면 제출 버튼이 스피너와 함께 `대표 이미지를 만드는 중…`을 표시하고 입력란이 잠긴다. 첫 화면 캡처가 끝나면 그 이미지를 대표 이미지로 프로젝트를 공개하고 지금처럼 상세 페이지로 이동한다.
- 첫 화면을 찍지 못하면 프로젝트를 만들지 않고, 프로젝트 URL 입력란에 오류 상태와 함께 `프로젝트 URL을 열 수 없어요. 주소가 맞는지, 로그인 없이 열리는지 확인해 주세요.`를 표시한다. 입력한 내용은 유지된다.
- 캡처 버튼, 이미지를 비워 두면 자동으로 만든다는 안내 문구는 두지 않는다.

### 공개 뒤 하이라이트 채우기

- 자동 캡처로 공개된 프로젝트는 백그라운드에서 하이라이트 화면을 최대 4장 더 찍어, 찍힌 순서대로 갤러리 뒤에 추가한다. 전체는 5장을 넘지 않는다.
- 진행 중임을 알리는 문구, 자리표시 칸, 알림은 소유자와 방문자 모두에게 보여주지 않는다. 다시 불러온 화면에 추가된 이미지가 그냥 보인다.
- 하이라이트 캡처가 실패하거나 찍을 화면을 찾지 못하면 아무것도 추가하지 않고 첫 화면 한 장으로 남는다. 소유자에게 오류를 보여주지 않는다.
- 소유자는 자동으로 추가된 이미지를 편집에서 직접 올린 이미지와 똑같이 순서를 바꾸거나 지울 수 있다.

### 편집

- 편집 저장도 같은 규칙을 따른다. 이미지를 모두 지우고 저장하면 저장 버튼이 `대표 이미지를 만드는 중…`을 표시하며 첫 화면을 기다리고, 저장 뒤 하이라이트를 다시 채운다. 첫 화면을 찍지 못하면 저장하지 않고 제출과 같은 오류를 보인다.
- 이미지가 1장 이상 남아 있으면 URL을 바꿔도 다시 캡처하지 않는다.
- 백그라운드 캡처가 도는 동안 소유자가 이미지를 바꾸면, 그 뒤에 도착한 자동 캡처는 추가하지 않는다.

### 하이라이트 에이전트

- 모델은 Claude Haiku 5.5이고, 한 번의 실행에서 행동은 최대 30번이다.
- 매 행동마다 목표, 지금까지 한 행동의 요약, 현재 화면 한 장만 모델에 보낸다. 지난 화면을 쌓지 않는다.
- 클릭, 스크롤, 키 입력, 짧고 무해한 예시 값 입력, 기다리기, 뒤로 가기, 화면 저장, 종료만 할 수 있다. 회원가입·로그인·결제·삭제·메시지 전송을 하지 않고 프로젝트 주소의 호스트 밖으로 나가지 않는다.
- 같은 화면은 두 번 저장하지 않는다.

### 사용 대상

- 클래스와 관계없이 모든 로그인 사용자에게 같은 규칙을 적용한다.

## 수용 기준

1. 이미지를 1장 이상 올리고 제출하면 올린 이미지만 순서대로 가진 프로젝트가 공개되고, 자동 캡처 실행 기록이 생기지 않는다.
2. 이미지 없이 공개 URL을 넣고 제출하면, 대기 중에 제출 버튼이 비활성화되고 `대표 이미지를 만드는 중…`을 보이며, 완료 후 해당 URL의 첫 화면(가로형 데스크톱 화면)을 대표 이미지 1장으로 가진 프로젝트가 공개되고 상세 페이지로 이동한다.
3. 존재하지 않는 도메인, 응답하지 않는 주소, 오류 상태 코드를 돌려주는 주소를 넣고 이미지 없이 제출하면 프로젝트가 만들어지지 않고 URL 입력란에 정해진 오류 문구가 보이며, 다른 입력값은 그대로 남는다.
4. 2번으로 공개된 프로젝트는 공개 후 3분 안에 이미지가 2~5장이 되거나, 하이라이트를 찾지 못한 경우 1장으로 남는다. 어느 경우에도 이미지는 5장을 넘지 않고, 첫 이미지는 바뀌지 않는다.
5. 하이라이트가 채워지는 동안과 그 뒤에 상세·보드 화면 어디에도 진행 안내 문구나 자리표시 칸이 나타나지 않는다. 다시 불러오면 추가된 이미지가 갤러리와 상세 썸네일 줄에 보인다.
6. 편집에서 이미지를 모두 지우고 저장하면 2~4번과 같은 결과가 나오고, 이미지를 남긴 채 URL만 바꿔 저장하면 이미지가 바뀌지 않는다.
7. 하이라이트 캡처가 진행 중일 때 소유자가 편집에서 이미지를 바꾸면, 이후 프로젝트 이미지는 소유자가 저장한 그대로 유지된다.
8. 하이라이트 에이전트는 한 실행에서 행동 30번을 넘지 않고, 프로젝트 호스트 밖의 페이지를 저장하지 않으며, 로그인·회원가입 화면을 거쳐 진행하지 않는다.
9. 한글이 있는 프로젝트의 캡처에서 한글이 네모 상자가 아닌 글자로 보인다.
10. 한 사용자가 하루 상한을 넘겨 자동 캡처 제출을 하면 제출은 2번처럼 첫 화면으로 성공하지만 하이라이트는 추가되지 않는다.
11. 하이라이트 실행 한 번의 평균 비용(모델 + 실행 환경)은 15원 이하이다.

## 제약과 근거

- 첫 화면은 제출을 기다리게 해서 확보한다. 공개된 프로젝트에 항상 대표 이미지가 있어 보드·상세·공유 미리보기에 빈 상태가 필요 없다. 근거와 버린 대안은 project-publishing 결정에 있다.
- 외부 URL은 Vercel Sandbox(1 vCPU / 2GB, 서울 리전) 안의 브라우저에서만 연다. 사용자는 아무 URL이나 넣을 수 있고 앱 함수에는 비밀 키가 있기 때문이다. 근거는 project-url-capture 결정에 있다.
- 첫 화면 대기는 10~20초 안에 끝나야 한다. 크롬과 한글 폰트를 미리 설치해 둔 상태에서 Sandbox를 시작해야 이 시간을 지킬 수 있다. 매번 설치하면 약 1분이 걸린다.
- 하이라이트는 Haiku 5.5 에이전트로 찍는다. 실제 하이라이트는 대부분 조작해야 나오고, 10개 프로젝트 평가에서 Haiku 5.5가 회당 약 8원으로 이런 화면에 도달했다.
- 비용은 Vercel Pro 플랜의 월 크레딧과 Anthropic API 사용량 안에서 감당하는 것을 전제로 한다. 비용 최적화가 이 기능의 최우선 제약이다.

## 범위 밖

- 캡처 버튼, 다시 찍기 버튼: 이미지를 비워 두는 것만으로 동작하므로 필요 없다고 결정했다.
- 자동 캡처 진행 안내, 자리표시 칸, 완료 알림: 소유자가 불필요한 안내로 판단했다.
- 이미지 장수 제한(1~5장)과 대표 이미지 규칙 변경: 기존 결정을 그대로 유지한다.
- 보드·상세·공유 미리보기의 이미지 없는 상태: 공개된 프로젝트는 항상 이미지가 있으므로 만들지 않는다.

## 가정

다음은 사용자가 반대하지 않은 기본값이며 바꿀 수 있다.

- 캡처 화면 크기는 1280×800 데스크톱이다.
- 하이라이트 캡처(모델 사용)는 사용자당 하루 10회까지다. 첫 화면 캡처는 모델을 쓰지 않으므로 제한하지 않는다.
- 하이라이트 실행 한 번은 3분 안에 끝나도록 자른다.
- "URL을 열 수 없음"은 페이지 이동 실패, 30초 안에 응답 없음, 400 이상 상태 코드를 뜻한다.
- 자동으로 찍힌 이미지는 편집 화면에서 직접 올린 이미지와 구분해 표시하지 않는다.

## 보류 사항

- 로그인이 필요한 프로젝트: 표본의 약 20%였고, 이번 범위에서는 로그인 화면이 대표 이미지가 된다. 시험용 계정을 받는 방식 등은 별도 작업에서 정한다.
- 원할 때 다시 찍기: 지금은 이미지를 모두 지우고 저장하는 것으로만 다시 찍는다.
- 모바일 화면 크기로 찍기.

## 남은 위험

- 같은 프로젝트라도 실행할 때마다 찍히는 화면이 다르다. 평가에서 같은 퀴즈가 5장과 1장으로 갈렸다.
- 에이전트가 버튼을 누르면서 학생 앱의 데이터가 생기거나 학생 앱이 쓰는 AI API 사용량이 소모될 수 있다.
- Sandbox 기본 이미지(Ubuntu 26.04)는 Playwright 1.59가 공식 지원하지 않아 Ubuntu 24.04 대체 빌드로 동작했다. Sandbox 이미지나 Playwright 버전이 바뀌면 다시 확인해야 한다.
- 느린 사이트는 첫 화면 대기가 20초를 넘을 수 있다.
- 평가 10개 중 2개(검색 결과가 비는 앱)는 앱 문제인지 에이전트 한계인지 구분하지 못했다.
- Haiku 5.5는 안전 거절 시 대체 모델로 넘어가는 기능이 없어, 거절되면 하이라이트 없이 끝난다.

## Setup before implementation

- 운영용 Anthropic API 키가 claude-hunt Vercel 프로젝트의 Production·Preview 환경에서 쓸 수 있게 등록되어 있어야 한다 (하이라이트 에이전트용). 완료 조건: 그 키로 앱 밖에서 `claude-haiku-5-5`에 직접 요청해 응답을 받는다.
- Anthropic Console에서 이 키가 속한 워크스페이스에 월 지출 한도(예: $10)를 설정한다 (비용 상한). 완료 조건: Console의 한도 화면에 설정값이 보인다.
- Vercel 팀 odd-inc의 claude-hunt 프로젝트에서 Sandbox를 만들 수 있어야 한다 (격리된 브라우저 실행). 완료 조건: 이번 shaping에서 `sandbox create --project claude-hunt --scope odd-inc --region icn1`로 생성에 성공해 이미 충족했다.
