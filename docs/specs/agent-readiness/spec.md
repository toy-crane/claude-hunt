# 에이전트 준비도 — 공개 표면의 기계 접근성

## 목적

Claude Hunt의 공개 표면을 AI 에이전트가 JavaScript 실행 없이 읽고, 실패에서 스스로
복구하고, API 표면을 자동으로 이해할 수 있게 만든다. 근거는 Is Agentic 감사
(현재 55/100)의 Essential 항목 5건이며, 사용자가 이 5건의 수정을 우선순위 그대로
지시했다. 브라우저 사용자의 화면과 제품 동작은 그대로 유지한다.

`PRODUCT.md`의 관련 전제: 로그인하지 않은 방문자도 월간 하이라이트, 전체 프로젝트
보드, 프로젝트 상세와 공개된 의견을 둘러볼 수 있다(공개 열람과 소유권 경계 분리).
이 작업은 그 공개 열람 표면을 기계가 읽을 수 있는 형태로 확장할 뿐, 열람 범위
자체를 넓히지 않는다.

## 사용자 가시 결과

1. **JS 없이 보이는 홈** — 홈의 원본 HTML에 H1과 이달의 하이라이트 내용(제품 정의
   문장 포함, 가시 텍스트 500자 이상)이 숨김 처리 없이 담긴다. 브라우저 화면
   디자인은 변하지 않는다.
2. **복구를 돕는 404** — 존재하지 않는 경로는 지금처럼 실제 HTTP 404를 반환하되,
   본문이 사이트 디자인과 일치하는 안내 페이지가 되어 홈, 프로젝트 보드,
   `/sitemap.xml`, `/llms.txt`로 가는 링크를 담는다. 마크다운을 요청한 에이전트는
   같은 링크를 담은 짧은 마크다운 404 본문을 받는다.
3. **공개 읽기 API와 OpenAPI 명세** — 익명 방문자에게 이미 공개된 프로젝트·클래스
   사실을 읽는 최소 API가 생기고, `/openapi.json`이 그 전체 표면을 기술한다.
4. **구조화된 JSON 오류** — 모든 API 응답(알 수 없는 API 경로 포함)의 오류는
   코드·메시지·해결 힌트를 가진 JSON이다. HTML 오류 페이지가 API 경로에 나타나지
   않는다.
5. **마크다운 콘텐츠 협상** — 공개 콘텐츠 페이지(홈, 프로젝트 보드, 프로젝트 상세,
   이용약관, 개인정보 처리방침)는 `Accept: text/markdown` 요청에 같은 URL에서
   깨끗한 마크다운을 반환하고, 모든 협상 응답에 `Vary: Accept`가 붙는다.
6. **llms.txt** — `/llms.txt`가 llmstxt.org 형식으로 사이트 개요와 핵심 진입점
   (핵심 페이지, sitemap, OpenAPI)을 안내한다. 404 안내와 OpenAPI 발견의 착지점
   역할을 한다.

## 승인된 범위

### 1. 홈 무-JS 콘텐츠

- 홈 응답의 원본 HTML에서, 스크립트·스타일·템플릿·`hidden` 처리된 조각을 제외한
  가시 콘텐츠에 H1과 이달의 클로드 헌트 내용(순위, 프로젝트 제목, 소개, 클래스,
  추천 수)이 포함된다.
- 홈 원본 HTML에 `PRODUCT.md`의 제품 정의 문장(클로드 헌트가 무엇인지)을 담아,
  프로젝트가 없는 달에도 가시 텍스트가 500자 이상 유지되게 한다. 이 문장은 화면
  디자인을 바꾸지 않는 방식(예: 스크린리더 전용)으로 넣을 수 있다.
- 콘텐츠 신선도는 지금과 같다: 프로젝트 등록·수정·삭제가 반영되는 기존 캐시 무효화
  의미를 유지한다.

### 2. 404 응답

- 존재하지 않는 모든 페이지 경로: HTTP 404 상태 + 사이트 공통 디자인(헤더·푸터
  포함)의 한국어 안내 페이지. 안내 문구는 기존 결의 톤("프로젝트를 찾을 수
  없어요")과 일치시키고, 홈 · 프로젝트 보드 · `/sitemap.xml` · `/llms.txt` 링크를
  담는다.
- 마크다운을 선호하는 `Accept` 요청에는 같은 404 상태로 같은 링크를 담은 짧은
  `text/markdown` 본문을 반환한다.
- 존재하지 않는 `/api/*` 경로: HTTP 404 + 아래 4번의 JSON 오류 형식.

### 3. 공개 읽기 API + OpenAPI 명세

- 익명으로 접근 가능한 읽기 전용 엔드포인트:
  - 프로젝트 목록 — 전체 공개 프로젝트. 기본 정렬은 추천 수 내림차순, 동률은 최신
    순(홈 하이라이트와 같은 규칙). 클래스 필터를 쿼리 파라미터로 지원하며 필터
    값은 클래스의 안정 이름이다(class-catalog 결정: 동작은 label이 아니라 안정
    `name`에 묶는다).
  - 프로젝트 단건 — 상세 페이지가 공개하는 사실.
  - 클래스 목록 — 클래스 안정 이름, 표시 label, 표시 순서(class-catalog의 결정된
    순서), 소속 프로젝트 수. TOYCRANE도 보드에서처럼 노출된다.
- 프로젝트가 노출하는 필드는 공개 화면이 이미 보여주는 사실로 한정한다: 프로젝트
  id, 제목, 한 줄 소개, 상세 설명, 실행 URL, GitHub URL, 순서 있는 이미지 URL,
  클래스(안정 이름·label), 작성자 표시 이름, 추천 수, 등록·수정 시각, 사이트 상세
  페이지 URL. 이 목록 밖의 필드(내부 사용자 id, 이메일 등)는 노출하지 않는다.
- `/openapi.json`: HTTP 200, `application/json`, 유효한 OpenAPI 3.1 문서. 위의
  모든 공개 엔드포인트, 파라미터, 응답 스키마, 오류 스키마를 기술하며, 실제 응답이
  문서와 일치한다. 서버 URL은 `https://www.claude-hunt.com`.

### 4. JSON 오류 응답

- 모든 `/api/*` 오류 응답은 `application/json`이고, 안정적인 오류 코드, 사람이
  읽을 메시지, 해결 힌트(다음에 무엇을 하면 되는지)를 담는 하나의 일관된 구조를
  따른다. 이 구조는 OpenAPI 오류 스키마와 동일하다.
- 최소 오류 상황: 형식이 잘못된 프로젝트 id(404 — 존재하지 않음과 동일 취급,
  프로젝트 상세 페이지의 기존 규칙과 일치), 없는 프로젝트 id(404), 알 수 없는 쿼리
  파라미터 값(400), 알 수 없는 `/api/*` 경로(404).
- 기존 테스트 전용 경로도 예외가 아니다: 프로덕션의 `/api/draft`는 현재 text/plain
  404를 반환하는데, 이를 알 수 없는 `/api/*` 경로와 구별 불가능한 같은 404 JSON
  오류 형식으로 바꾼다. 비프로덕션에서의 draft mode 활성화 동작은 그대로 둔다.

### 5. 마크다운 콘텐츠 협상 (acceptmarkdown.com 준수)

- 대상 URL: `/`, `/projects`, `/projects/{id}`, `/privacy`, `/terms`, 그리고
  페이지 404 응답. 인증 전용 페이지와 단일 표현 기계 파일(sitemap, robots,
  openapi, llms.txt, 이미지)은 협상 대상이 아니다.
- `Accept` 파싱은 문자열 포함 검사가 아니라 q값 정렬·구체성 우선·`q=0` 배제 규칙을
  따른다:
  - 마크다운을 HTML보다 선호하면 `Content-Type: text/markdown; charset=utf-8`으로
    마크다운을 반환한다.
  - `Accept` 없음 또는 `*/*` 등 HTML을 배제하지 않는 요청은 지금처럼 HTML을
    반환한다(브라우저 동작 불변).
  - 제공 가능한 표현(text/html, text/markdown)이 모두 배제된 요청(예:
    `Accept: application/pdf`)은 HTTP 406과, 제공 가능한 표현을 나열한
    `text/plain` 본문을 반환한다. 406은 공격적으로 캐시하지 않는다.
- 협상 대상 URL의 모든 응답(HTML 변형과 마크다운 변형 모두)의 `Vary` 헤더에
  `Accept`가 포함된다. 프레임워크가 이미 설정하는 기존 `Vary` 값은 제거하지 않고
  유지한다(클라이언트 내비게이션 캐시 정확성).
- CDN을 거쳐도 표현이 섞이지 않는다: 같은 URL에 HTML 요청과 마크다운 요청을
  번갈아 보내면 각각 항상 올바른 표현이 온다(캐시 적중 상태 무관).
- 마크다운 변형의 내용은 같은 URL의 HTML이 보여주는 공개 콘텐츠와 같은 사실을
  담는다: 홈은 제품 정의와 이달의 하이라이트, 보드는 전체 프로젝트 목록(제목·한 줄
  소개·클래스·추천 수·상세 링크), 상세는 프로젝트 사실과 공개된 의견(댓글·답글
  텍스트, 작성자 표시 이름, 반응 수), 약관·방침은 전문. 신선도 의미는 HTML과 같다.

### 6. llms.txt

- `/llms.txt`: HTTP 200, llmstxt.org 형식(H1 프로젝트명, 요약 blockquote, 링크
  섹션). 한국어. 핵심 페이지(홈, 프로젝트 보드), 기계 파일(`/sitemap.xml`,
  `/openapi.json`), 정책 페이지를 안내하고, 콘텐츠 페이지가
  `Accept: text/markdown` 협상을 지원한다는 사실을 명시한다.

### 검증과 테스트

- 변경되는 모든 동작에 테스트를 추가하거나 갱신한다(프로젝트 테스트 원칙: 성공
  기준마다 그것을 증명하는 테스트).
- 배포 후 프로덕션 URL에 대해 아래 수용 기준의 curl 검증을 모두 수행하고 결과를
  보고한다.

## 관찰 가능한 수용 기준

프로덕션(`https://www.claude-hunt.com`) 기준. 로컬에서도 동일하게 검증 가능해야
한다.

1. `curl -s /` 결과에서 스크립트·스타일·템플릿·`hidden` 조각을 제외한 텍스트가
   500자 이상이고, H1과 제품 정의 문장, 이달의 프로젝트 제목들이 포함된다.
2. `curl -s -o /dev/null -w "%{http_code}" /some-path-that-does-not-exist` → `404`.
   본문에 홈·프로젝트 보드·`/sitemap.xml`·`/llms.txt` 링크가 있다.
   `-H "Accept: text/markdown"`로 같은 경로 요청 → `404` +
   `Content-Type: text/markdown` + 같은 링크.
3. `curl -s /openapi.json` → `200`, `application/json`, OpenAPI 3.1로 유효(검증
   도구 통과). 문서의 모든 엔드포인트가 실제로 문서대로 응답한다.
4. 프로젝트 목록 API → `200` JSON, 추천 수 내림차순·동률 최신순. 클래스 안정
   이름으로 필터하면 해당 클래스만 온다. 없는 id·잘못된 형식의 id 단건 조회 →
   `404` JSON 오류(코드·메시지·힌트). 알 수 없는 필터 값 → `400` JSON 오류. 없는
   `/api/*` 경로 → `404` JSON 오류. 프로덕션 `curl -s /api/draft` → `404` +
   `application/json` + 같은 오류 스키마(text/plain 아님). 어떤 API 오류도 HTML이나
   플레인 텍스트가 아니다.
5. 협상 대상 5종 URL 각각에 대해:
   - `-H "Accept: text/markdown"` → `200`,
     `Content-Type: text/markdown; charset=utf-8`, `Vary`에 `Accept` 포함, 본문은
     해당 페이지의 공개 콘텐츠 마크다운.
   - `Accept` 없이 → 기존과 같은 HTML, `Vary`에 `Accept` 포함, 기존 `Vary` 값
     유지.
   - `-H "Accept: text/markdown;q=0.5, text/html"` → HTML.
     `-H "Accept: text/html;q=0.8, text/markdown"` → 마크다운(q값 존중).
   - `-H "Accept: application/pdf"` → `406` + 제공 표현을 나열한 text/plain 본문.
   - 같은 URL에 HTML → 마크다운 → HTML 순서로 요청해도 각 응답의 표현이 항상
     요청과 일치한다(CDN 캐시 워밍 후 포함).
6. `curl -s /llms.txt` → `200`, llmstxt.org 구조(H1 + blockquote + 링크 섹션),
   나열된 링크가 모두 200으로 응답.
7. 회귀 없음: 브라우저 기준 홈·보드·상세의 화면 구성과 상호작용, `/sitemap.xml`,
   `/robots.txt`, 인증·온보딩 흐름이 기존과 동일하게 동작한다. 기존 테스트 전부
   통과.

## 확정 제약과 근거

- **협상은 오직 `Accept` 헤더로만 한다.** User-Agent 판별로 에이전트에게 다른
  콘텐츠를 주는 방식(클로킹)은 금지. 같은 요청에는 누구에게나 같은 응답 — 검색
  엔진 신뢰와 감사 재현성을 지킨다.
- **API·마크다운 변형이 노출하는 데이터는 익명 방문자가 공개 화면에서 이미 볼 수
  있는 사실의 부분집합이다.** 공개 열람과 소유권 경계(PRODUCT.md, project-publishing
  결정)를 기계 표면에서도 동일하게 유지한다.
- **API 용어는 GLOSSARY를 따른다.** 클래스 개념의 영문 키는 `class`(값은 안정
  이름), 추천 수는 `recommendation_count`. 사용자 표면에서 피하는 용어(vote,
  cohort)를 새 공개 계약에 들이지 않는다.
- **`Vary`의 기존 값 유지.** 프레임워크가 넣는 값들을 제거하면 클라이언트
  내비게이션 캐시가 깨진다. `Accept`는 추가만 한다.
- **404·406·오류 응답도 프로토콜대로.** 404는 진짜 404 상태(앱 셸 200 금지),
  406은 제공 표현 목록을 담은 본문과 함께 드물게만, API 오류는 항상 JSON.
- **서비스 문구는 한국어 기준**(PRODUCT.md). 404 안내, llms.txt, 마크다운 변형,
  API 오류 메시지·힌트는 한국어. API 오류 코드만 기계 안정성을 위해 영문
  snake_case.

## 가정 (재정의 가능)

- API 경로는 버전 없는 `/api/projects`, `/api/projects/{id}`, `/api/classes`를
  사용한다. 파괴적 변경이 필요해지는 시점에 버전 도입을 다시 판단한다.
- OpenAPI 문서는 `/openapi.json` 단일 경로면 충분하다(`/api/openapi.yaml` 별도
  제공 안 함).
- 프로젝트 상세 마크다운 변형에 공개 의견을 포함한다(화면이 이미 공개하는 내용).
  분량이 문제 되면 의견을 제외하는 축소는 재정의 가능.
- 홈의 500자 하한 보강은 제품 정의 문장으로 충분하며, 새 가시 카피를 추가하지
  않는다.
- 406 본문은 acceptmarkdown.com 권고대로 text/plain으로 충분하다.
- 프로젝트 목록 API는 현재 규모(약 130건)에서 페이지네이션 없이 전체를 반환한다
  (recommendations-and-ranking 결정의 "재검토 시점"과 동일 조건에서 재검토).

## 범위 밖

- **쓰기 API 없음** — 제출·추천·의견을 API로 받지 않는다. 인증·남용 방지 표면이
  전혀 다른 작업이고, 이번 감사 항목이 요구하지 않는다.
- **감사 5건 + llms.txt 밖의 최적화 없음** — llms-full.txt, 구조화 데이터 확장,
  기타 SEO/AI-SEO 작업은 이번 단위에 넣지 않는다.
- **인증 전용 페이지의 협상·무-JS 대응 없음** — noindex 대상이며 에이전트 열람
  표면이 아니다.
- **robots.txt·sitemap.xml 의미 변경 없음** — 이미 감사를 통과한 표면이다.
- **브라우저 화면·상호작용 변경 없음** — 이 작업의 성공 조건 자체가 "화면은
  그대로"다.

## 보류 (이번 단위에서 결정하지 않음)

- API의 월(month) 필터, 검색, 페이지네이션 파라미터 — 에이전트가 전체 목록으로
  계산 가능하므로 수요가 확인될 때 추가.
- 에이전트 표면 전용 rate limiting — 현재는 플랫폼(호스팅·데이터베이스 익명 권한)
  기본값에 맡긴다.
- 이 작업이 만드는 "공개 기계 표면 유지 규칙"(Vary 유지, 협상 대상 URL 집합, 공개
  필드 경계)의 결정 계약 승격 — 구현이 출하되어 실제 형태가 확정된 뒤
  `project-knowledge`로 기록한다.

## 남은 리스크

- **공개 API는 암묵적 외부 계약이 된다.** 한번 공개된 필드·경로 변경은 소비자를
  깨뜨린다. 최소 표면과 OpenAPI 단일 진실로 완화하지만, 향후 스키마 변경 작업은 이
  표면을 회귀 대상으로 취급해야 한다.
- **CDN의 `Vary: Accept` 처리.** 호스팅 엣지 캐시가 변형별 캐시를 올바르게
  분리하는지는 배포 후 프로덕션에서만 최종 확인 가능하다(수용 기준 5의 교차 요청
  검증이 게이트).
- **홈 첫 바이트 지연.** 하이라이트 내용을 숨김 조각이 아닌 가시 HTML로 내려면 첫
  응답이 데이터 준비를 기다릴 수 있다. 기존 캐시가 조회를 이미 흡수하고 있어 영향은
  작다고 판단하나, 배포 후 체감 확인이 필요하다.
- **감사 도구의 측정 방식은 비공개다.** 수용 기준은 감사 문구보다 보수적으로(가시
  텍스트 기준 500자 + 여유분) 잡았지만, 재감사 점수는 도구의 재량에 달려 있다.
- **406 도입.** 표준을 따르는 응답이지만, `*/*` 없이 이례적 `Accept`를 보내는
  구형 클라이언트가 협상 대상 페이지에서 406을 받게 된다. 브라우저는 모두 `*/*`를
  보내므로 실사용 영향은 없다고 판단한다.
