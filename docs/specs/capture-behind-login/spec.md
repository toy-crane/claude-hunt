# 로그인이 필요한 프로젝트의 자동 캡처

## 목적

자동 캡처가 로그인 화면에 막혀 로그인 화면 한 장만 남는 프로젝트도 실제 사용 화면을 보여 주게 한다. 하이라이트 에이전트는 소유자가 상세 설명에 적은 접속 정보로 로그인하고, 정보가 없으면 간단한 회원가입을 한 뒤 하이라이트를 찍는다. 로그인 뒤 화면을 찍으면 로그인 화면 대신 그 화면을 대표 이미지로 쓴다.

## 연결된 기준

- [project-url-capture](../../decisions/project-url-capture.md) — 외부 URL을 격리된 Sandbox에서만 여는 규칙, 에이전트 행동 경계, 로그인·가입을 허용하는 조건, 접속 정보의 출처와 보관 금지를 정한다.
- [project-publishing](../../decisions/project-publishing.md) — 이미지 1～5장 불변식, 대표 이미지 규칙, 첫 화면이 로그인 화면일 때만 대표 이미지를 바꾸는 예외, 소유자 변경 우선 규칙을 정한다.
- [auto-project-images 스펙](../auto-project-images/spec.md) — 지금 동작하는 자동 캡처의 제출 대기, 화면과 문구, 하이라이트 장수·행동·시간·하루 실행 한도를 정한다. 이 작업은 그 위에 로그인 처리만 더하며, 그 스펙이 보류한 "로그인이 필요한 프로젝트"를 여기서 정한다.
- [follow-up: 캐시된 화면에 자동 캡처가 늦게 보임](../../follow-ups/auto-captured-images-appear-late-on-cached-pages.md) — 백그라운드에서 바뀐 이미지가 보드·상세에 늦게 반영되는 문제. 대표 이미지 교체도 같은 지연을 겪는다.
- [GLOSSARY.md](../../../GLOSSARY.md) — `대표 이미지`, `프로젝트`의 뜻.
- [PRODUCT.md](../../../PRODUCT.md) — 이 작업에 적용되는 원칙은 "프로젝트 제출의 마찰을 낮춘다"와 "프로젝트가 장식이나 운영 도구보다 먼저 보이게 한다"이다.

## 기대 결과

- 상세 설명에 테스트 계정이 적힌 로그인 필수 프로젝트는 공개 후 몇 분 안에 보드 카드, 상세 갤러리, 공유 미리보기가 로그인 뒤의 실제 화면으로 바뀐다.
- 계정이 적혀 있지 않아도 프로젝트에 간단한 가입 양식이 있으면 같은 결과가 난다.
- 로그인 없이 쓸 수 있는 프로젝트와 이미지를 직접 올린 프로젝트는 지금과 똑같이 동작한다.
- 소유자가 새로 입력하거나 더 기다리는 것은 없다. 제출·편집 화면과 문구는 바뀌지 않는다.

## 승인된 범위

### 언제 로그인을 시도하는가

- 자동 캡처의 하이라이트 단계에서만 시도한다. 제출할 때 기다리는 첫 화면 캡처는 지금처럼 모델 없이 찍는다.
- 로그인하지 않으면 핵심 기능을 볼 수 없을 때만 시도한다. 첫 화면이 로그인·가입 화면이거나 핵심 기능을 누르면 로그인을 요구하는 경우다. 로그인이 선택 기능일 뿐인 앱에서는 로그인도 가입도 하지 않는다.

### 접속 정보

- 에이전트는 프로젝트의 상세 설명에서만 접속 정보(아이디와 비밀번호, 공용 비밀번호, 입장 코드 등)를 찾는다. 댓글은 소유자가 쓴 것을 포함해 읽지 않는다.
- 상세 설명에 접속 정보가 있으면 먼저 그것으로 로그인한다.
- 공개한 뒤에 상세 설명에 계정을 적은 소유자는 지금처럼 이미지를 모두 지우고 저장해야 다시 찍힌다.

### 회원가입

- 상세 설명에 접속 정보가 없거나 그 정보로 로그인하지 못했고 화면에 가입 양식이 있으면, 소유자에게 따로 묻지 않고 가입한다.
- 이메일 인증, 휴대폰 인증, CAPTCHA, 구글·카카오 같은 소셜 로그인이 필요하면 가입하지 않는다.
- 로그인과 가입은 프로젝트 주소의 호스트 안에 있는 양식에서만 한다. 다른 호스트의 인증 화면으로 넘어가면 아무것도 입력하지 않는다.
- 가입 정보는 Claude Hunt 캡처 계정임을 알아볼 수 있게 채운다. 약관은 가입에 필수인 항목에만 동의한다.

### 대표 이미지

- 첫 화면이 로그인·가입 화면이었고 에이전트가 그 뒤 화면을 찍으면, 로그인 뒤 처음 찍은 화면이 대표 이미지가 되고 로그인 화면은 갤러리에서 빠진다. 이어서 찍은 화면은 그 뒤에 붙는다.
- 로그인·가입에 실패하거나 로그인 뒤 찍을 화면을 찾지 못하면 로그인 화면이 대표 이미지로 남는다. 소유자에게 오류를 보여 주지 않는다.
- 첫 화면은 로그인 화면이 아니었고 탐색 도중에 로그인한 경우에는 대표 이미지를 바꾸지 않고 지금처럼 뒤에 붙인다.
- 캡처가 도는 동안 소유자가 이미지를 바꾸면 교체도 추가도 하지 않는다.
- 로그인·가입 양식이 보이는 화면은 하이라이트로 저장하지 않는다.

### 보관

- 상세 설명에서 읽은 접속 정보와 가입에 쓴 비밀번호는 한 번의 실행 안에서만 쓴다. Claude Hunt의 데이터베이스, 실행 기록, 서버 로그, 오류 추적 어디에도 남기지 않는다.

### 사용 대상

- 자동 캡처와 같다. 이미지 없이 제출하거나 이미지를 모두 지우고 저장한 모든 로그인 사용자에게 적용한다.

## 수용 기준

1. 첫 화면이 프로젝트 호스트의 로그인 양식이고 상세 설명에 맞는 아이디와 비밀번호가 적힌 프로젝트를 이미지 없이 제출하면, 공개 직후 대표 이미지는 로그인 화면이고, 공개 후 3분 안에 대표 이미지가 로그인 뒤의 화면으로 바뀐다. 갤러리는 1～4장이고 로그인 양식이 보이는 이미지는 하나도 없다.
2. 1과 같은 앱인데 상세 설명에 접속 정보가 없고 인증 없이 끝나는 가입 양식이 있으면, 1과 같은 결과가 나고 그 앱에 Claude Hunt 캡처용 주소로 만든 계정이 하나 생긴다.
3. 상세 설명의 비밀번호가 틀렸을 때 가입 양식이 있으면 2처럼 가입해서 찍고, 가입 양식이 없으면 로그인 화면 한 장으로 남는다.
4. 가입에 이메일 인증, 휴대폰 인증, CAPTCHA, 소셜 로그인 중 하나가 필요한 앱은 로그인 화면 한 장으로 남고, 소유자에게 오류가 보이지 않는다.
5. 로그인 버튼이 다른 호스트의 인증 화면으로 이동하는 앱에서는 그 화면에 아무것도 입력되지 않고 로그인 화면 한 장으로 남는다.
6. 다른 사용자나 소유자가 댓글에 계정을 적어도 에이전트 동작은 달라지지 않는다. 댓글 내용은 모델에 전달되지 않는다.
7. 로그인 없이 쓸 수 있는 프로젝트는 대표 이미지가 바뀌지 않고 하이라이트가 지금처럼 뒤에 붙는다. 로그인이 선택 기능인 앱에서는 계정이 생기지 않는다.
8. 1이나 2가 진행되는 동안 소유자가 편집에서 이미지를 바꾸면, 이후 이미지는 소유자가 저장한 그대로 유지된다.
9. 실행이 끝난 뒤 데이터베이스(실행 기록 포함), 서버 로그, 오류 추적에서 상세 설명의 비밀번호나 가입에 쓴 비밀번호 문자열이 검색되지 않는다.
10. 로그인이나 가입을 포함해도 한 실행은 행동 30번과 3분을 넘지 않는다.
11. 이미지를 1장 이상 올리고 제출하면 지금처럼 자동 캡처도 로그인도 일어나지 않는다.
12. 로그인이나 가입을 포함한 하이라이트 실행 한 번의 평균 비용(모델 + 실행 환경)은 15원 이하이다.

## 제약과 근거

- 접속 정보는 상세 설명에서만 읽는다. 하이라이트는 제출 직후에 돌기 때문에 그때 이미 있는 소유자 글은 상세 설명뿐이고, 실제로 소유자들이 테스트 계정과 비밀번호를 상세 설명에 적고 있다(Tally, 동영상 다운로더). 댓글은 204개 프로젝트에 6개뿐이고, 다른 사용자의 글이 에이전트를 움직이지 못하게 막는 효과도 있다. 근거와 버린 대안은 project-url-capture 결정에 있다.
- 로그인에 막히면 소유자의 허락 없이도 가입한다. 아무것도 적지 않은 소유자의 로그인 필수 앱도 하이라이트를 얻게 하려는 선택이며, 학생 앱에 캡처 계정이 생기는 것을 그 대가로 받아들였다.
- 인증, CAPTCHA, 소셜 로그인이 필요한 가입은 하지 않는다. 메일을 받을 주소, 실제 개인 계정, 봇 차단 우회가 각각 필요하기 때문이다.
- 대표 이미지는 첫 화면이 로그인 화면일 때만 바꾼다. 로그인 화면은 프로젝트를 설명하지 못하기 때문이다. 공개된 프로젝트에 항상 대표 이미지가 있다는 원칙은 그대로이고, 바뀌는 것은 어떤 이미지인지뿐이다. 근거는 project-publishing 결정에 있다.
- 접속 정보와 비밀번호를 남기지 않는다. 공개된 글에서 읽은 정보라도 Claude Hunt가 다른 서비스의 자격 증명을 쌓아 두는 곳이 되면 안 된다.
- 비용을 최우선으로 하는 제약과 행동 30번·3분·하루 10회 한도는 기존 자동 캡처를 그대로 따른다.

## 범위 밖

- 댓글에서 접속 정보 읽기, 댓글이 달리면 다시 찍기: 정보 출처를 상세 설명으로 정했다.
- 제출 폼의 테스트 계정 전용 입력란과 안내 문구: 새 입력과 문구 없이 동작하게 정했다.
- 이메일·휴대폰 인증을 처리할 받은편지함: 필요해지면 project-url-capture 결정을 다시 연다.
- Vercel 배포 보호(`Log in to Vercel`) 화면: 앱의 로그인이 아니라 배포 설정 문제이고 vercel.com으로 나가야 한다. 첫 20회 실행 중 1건이었다.
- 명령어로 토큰을 만들어 넣어야 하는 앱처럼 사람이 직접 준비해야 하는 접속 방식.
- 학생 앱에 만든 캡처 계정 삭제.

## 가정

다음은 에이전트가 정한 기본값이며 바꿀 수 있다.

- 가입 이메일은 `@claude-hunt.com` 도메인에 실행마다 다른 이름을 붙인 주소다. 메일함은 만들지 않는다. Supabase Auth의 주소 검증은 A 레코드가 있는 이 도메인을 통과시킨다.
- 이름·닉네임 칸은 Claude Hunt 캡처 계정임을 알 수 있는 값으로 채우고, 중복이면 짧은 임의 문자를 붙인다. 가입 비밀번호는 실행마다 임의로 만든다.
- 로그인 처리를 해도 하이라이트는 최대 4장이다. 로그인 화면이 빠지면 갤러리는 1～4장이 된다.
- 로그인·가입에 쓰는 행동도 기존 30번·3분 한도에 포함하고, 한도를 늘리지 않는다.
- 상세 설명의 접속 정보로 로그인에 실패하면 가입을 시도한다.

## 보류 사항

- 원할 때 다시 찍기: auto-project-images에서 보류한 그대로다. 공개 뒤 상세 설명에 계정을 적은 소유자는 이미지를 모두 지우고 저장해야 한다.

## 남은 위험

- 누구나 아무 URL이나 제출할 수 있어서, 남이 운영하는 서비스에 Claude Hunt 캡처 계정이 생길 수 있다. 이를 막는 장치는 하루 실행 한도와 프로젝트 호스트 제한뿐이다.
- 학생 앱이 자체 메일 발송을 쓰면 가입 확인 메일이 받을 수 없는 주소로 가서 반송된다. 반송이 쌓이면 그 앱의 메일 발송에 불이익이 생길 수 있다. Supabase 기본 메일은 팀 밖 주소로 보내지 않으므로, 이메일 확인을 켠 Supabase 앱에서는 가입 자체가 실패한다.
- 이메일 인증이 필요한지는 양식을 제출해 봐야 알 수 있는 경우가 많아, 인증을 기다리는 계정이 학생 앱에 남을 수 있다.
- 상세 설명은 소유자가 쓴 자유로운 글이라 접속 정보 말고 다른 지시가 섞일 수 있다. 호스트 밖 이동은 브라우저 쪽에서 막지만, 결제·삭제·전송 금지는 모델의 판단에 기댄다.
- 로그인·가입에 행동을 쓰는 만큼 하이라이트에 쓸 행동이 줄어, 로그인 뒤 화면이 1～2장에 그칠 수 있다.
- 첫 화면이 로그인 화면인지 에이전트가 잘못 판단하면 멀쩡한 대표 이미지가 바뀔 수 있다.
- 대표 이미지가 공개 몇 분 뒤에 바뀌므로 그사이 공유된 링크의 미리보기에는 로그인 화면이 남을 수 있고, 보드에서도 캐시 때문에 교체가 늦게 보일 수 있다.
- 상세 설명의 계정이 테스트 계정이 아니라 실제 개인 계정이면 그 계정의 데이터가 스크린샷으로 공개된다.
